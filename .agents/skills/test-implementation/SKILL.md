# Skill: Implementar Tests

## REGLAS ABSOLUTAS
1. No implementar lógica de negocio — solo tests.
2. Solo editar archivos en `tests/`.
3. Cambios en código productivo solo si bloquean compilación — documentarlos en `errors.md`.
4. Un test = un Scenario = una responsabilidad.
5. No borrar tests existentes para hacer pasar otros.
6. No mockear red en E2E — tests corren contra app real local.
7. No usar `test.skip` sin comentario que explique por qué y quién lo desbloquea.

## FASE 1 — Leer matriz de trazabilidad

Leer `.agents/sprint/{STRY-XXX}/test-matrix.md`.

Si no existe → ejecutar `/test-spec` primero.

La matriz define exactamente qué tests crear. No crear tests fuera de ella sin justificación.

## FASE 2 — Estado de gaps (sin pausa)

Generar tabla interna de trabajo (no mostrar al usuario — continuar automáticamente):

| SC-ID | Scenario | Archivo destino | ¿Existe? | Acción |
|-------|----------|-----------------|----------|--------|
| SC-01 | ... | tests/e2e/... | No | Crear |
| SC-02 | ... | tests/unit/... | Parcial | Completar |

## FASE 3 — Crear tests faltantes

Para cada entrada de la matriz con estado ⬜ pendiente:

### E2E (Playwright)
```typescript
import { test, expect } from "@playwright/test";

test.describe("Feature: [nombre]", () => {
  // SC-01: [título del scenario]
  test("SC-01 — [Given/When/Then en una línea]", async ({ page }) => {
    // Given
    await page.goto("/t/wondernails/[ruta]");
    // When
    await page.getByRole("button", { name: "..." }).click();
    // Then
    await expect(page.getByText("...")).toBeVisible();
  });
});
```

### Unit (Vitest + Result Pattern)
```typescript
import { describe, it, expect } from "vitest";
import { expectSuccess, expectFailure } from "@sass-store/core/src/result/test-helpers";

describe("Feature: [nombre]", () => {
  // SC-02: [título del scenario]
  it("SC-02 — retorna Ok con [dato] cuando [condición]", async () => {
    const result = await funcion(inputValido);
    expectSuccess(result, (data) => {
      expect(data.campo).toBe(valorEsperado);
    });
  });

  // SC-03: [título del scenario de error]
  it("SC-03 — retorna Err cuando [condición de error]", async () => {
    const result = await funcion(inputInvalido);
    expectFailure(result, (error) => {
      expect(error.code).toBe("CODIGO_ERROR");
    });
  });
});
```

### API (curl en quality-runner / Vitest supertest)
Generar los comandos curl documentados en el test-spec para que `/quality-runner` los ejecute.

## FASE 4 — Actualizar matriz

Marcar cada Scenario implementado en `test-matrix.md`:
- ⬜ pendiente → ✅ implementado (con ruta del archivo)
- Si no se pudo implementar → ⚠️ bloqueado (con razón)

## FASE 5 — Verificar compilación

```bash
npm run build
npm run test:unit -- --run
```

- Si falla en tests nuevos → corregir (máx 3 intentos)
- Si falla en código productivo → documentar en `errors.md`, no corregir aquí
- Si falla al intento 3 → BLOQUEANTE

## FASE 6 — Actualizar memoria y auto-continuar

Actualizar `.agents/memory/workflow-state.json`:
```json
{
  "testImplementationStatus": "done",
  "currentStage": "quality-runner",
  "lastAgent": "test-implementation"
}
```

**Continuar automáticamente con Skill: quality-runner** — no esperar al usuario.
